# Manual Roadmap YAML Format Guide

## Overview

The Manual Roadmap feature allows you to define learning paths using **YAML** syntax. Your YAML is:
1. Stored as-is in the database (for future editing)
2. Parsed into a graph structure (nodes + edges)
3. Laid out automatically using ELK.js
4. Rendered with ReactFlow for interactivity

## Basic Structure

```yaml
title: Your Roadmap Title
description: A brief description of the learning path

nodes:
  - nodeId: unique-id-1
    type: main_topic              # One of: main_topic, sub_topic, group_container, choice_item
    roadmapName: Display Name
    description: Optional detailed description
    parentNodeId: null            # Parent node ID for hierarchy (null = root)
    skillName: skill-name-1        # Optional: single skill name
    resources:                     # Optional: learning materials
      - title: Resource Title
        url: https://example.com
        type: link                # One of: link, docs, course, video, book
    elkOptions:                    # Optional: ELK layout configuration
      width: 220
      height: 80

edges:                             # Optional: explicit edges (auto-generated by default)
  - id: e_1
    source: node-id-1
    target: node-id-2
    type: default                 # One of: default, dashed
```

## Node Types Explained

### 1. `main_topic` (Root nodes)
- Rendered as large boxes (220×80px)
- Typically the main learning areas
- Should have **no parent** (parentNodeId: null)
- Example: "Frontend Development", "Backend APIs", "DevOps"

### 2. `sub_topic` (Child nodes)
- Rendered as smaller boxes (160×60px)
- Children of main topics
- Must have a **parentNodeId** pointing to a main_topic
- Example: "HTML Basics", "CSS Styling", "JavaScript DOM"

### 3. `group_container` (Grouped sections)
- Visual container for related items
- Can have children nodes
- Example: "Installation Tools", "Testing Framework"

### 4. `choice_item` (Alternative paths)
- Represents optional or alternative learning paths
- Can be at any level
- Example: "Learn React OR Vue", "Use TypeScript OR JavaScript"

## Field Definitions

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| title | string | ✅ | Roadmap title (max 200 chars) |
| description | string | ❌ | Roadmap description (max 1000 chars) |
| nodes | array | ✅ | Array of node objects |
| edges | array | ❌ | Array of edge objects (auto-generated if omitted) |

### Node Fields

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| nodeId | string | ✅ | Unique identifier (no spaces, use kebab-case) |
| type | string | ❌ | Node type (default: main_topic) |
| roadmapName | string | ✅ | Display name |
| description | string | ❌ | Detailed explanation |
| parentNodeId | string | ❌ | ID of parent node (for hierarchy) |
| skillName | string | ❌ | Single skill name |
| resources | array | ❌ | Array of learning resources |
| elkOptions | object | ❌ | ELK.js layout configuration |
| metadata | object | ❌ | User-defined metadata |

### Resource Fields

| Field | Type | Required |
|-------|------|----------|
| title | string | ✅ |
| url | string | ✅ |
| type | string | ❌ (default: link) |

## Complete Example

```yaml
title: Full-Stack Engineering Bootcamp
description: Complete path from HTML to production deployment

nodes:
  - nodeId: frontend-core
    type: main_topic
    roadmapName: Frontend Fundamentals
    description: Learn the foundations of web development.
    parentNodeId: null
    skillName: html5
    resources:
      - title: MDN Web Docs
        url: https://mdn.org
        type: docs

  - nodeId: react-basics
    type: sub_topic
    roadmapName: React Basics
    description: Components, props, state, and hooks.
    parentNodeId: frontend-core
    skillName: react
    resources:
      - title: React Official Docs
        url: https://react.dev
        type: docs

  - nodeId: backend-core
    type: main_topic
    roadmapName: Backend Development
    description: REST APIs, databases, and authentication.
    parentNodeId: null
    skillName: nodejs

  - nodeId: devops-core
    type: main_topic
    roadmapName: DevOps & Deployment
    description: Docker, Kubernetes, and CI/CD.
    parentNodeId: null
    skillName: docker

edges:
  - id: e_frontend_to_react
    source: frontend-core
    target: react-basics
    type: dashed

  - id: e_backend_to_devops
    source: backend-core
    target: devops-core
    type: dashed
```

## Best Practices

### 1. Use kebab-case for IDs
✅ Good:
```yaml
nodeId: react-hooks-advanced
```

❌ Bad:
```yaml
nodeId: ReactHooksAdvanced
nodeId: react hooks advanced
```

### 2. Keep descriptions concise
✅ Good: "Learn React Hooks, state management, and custom hooks"
❌ Bad: "In this module we will learn about hooks which are..."

### 3. Set parentNodeId explicitly
- **parentNodeId** is for hierarchy (visual grouping)

```yaml
nodes:
  - nodeId: javascript
    type: main_topic
    parentNodeId: null          # This is a root node

  - nodeId: dom-manipulation
    type: sub_topic
    parentNodeId: javascript    # Parent for hierarchy ✅
```

### 4. Use multi-line descriptions with `|`
```yaml
description: |
  First paragraph of description.
  Second line.
  
  Second paragraph after blank line.
```

### 5. Limit main topics to 3-5 on a row
- Too many makes the graph unreadable
- Use sub_topics to organize

## Validation Rules

Your YAML will be validated for:

| Rule | Error Message |
|------|---------------|
| Missing `title` | "Roadmap title is required" |
| Missing `nodes` | "At least one node is required" |
| Missing `nodeId` | "Each node must have a 'nodeId' field" |
| Missing `roadmapName` | "Each node must have a 'roadmapName' field" |
| More than one skill | "Only one skillName is allowed" |
| Circular references | "Circular dependency detected" |
| Invalid parent references | "Parent node not found" |
| Duplicate nodeIds | "Duplicate node ID" |

## Editing Tips

### In Monaco Editor
- **Ctrl+/** (or Cmd+/) to comment lines
- **Ctrl+Z** to undo
- **Hover** to see validation errors (red underlines)
- **Ctrl+F** to find nodes

### Colors & Visual Feedback
- 🔵 main_topic nodes appear blue
- 🔵 sub_topic nodes appear light blue
- 🟣 group_container nodes appear purple
- 🔴 Validation errors shown in red

## Troubleshooting

**Problem**: Nodes not appearing in graph
- Check each nodeId is unique
- Check required fields (title, nodes array)
- Check YAML indentation (must be multiples of 2 spaces)

**Problem**: Nodes connected incorrectly
- Verify parentNodeId matches an existing nodeId
- Check for typos in IDs

**Problem**: Graph layout looks compressed
- Check node counts (too many nodes in one row → adjust parentNodeId)
- Adjust elkOptions if custom layout needed

## API Response Format

After saving, the roadmap is stored with both:
```json
{
  "_id": "...",
  "title": "...",
  "yamlCode": "... original YAML ...",     // For editing
  "nodes": [...],                            // Pre-parsed nodes
  "edges": [...],                            // Pre-computed edges
  "positions": {...},                        // ELK.js computed positions (cached)
  "status": "draft",
  "createdAt": "...",
  "updatedAt": "..."
}
```

- **Edit mode** uses `yamlCode` (to allow modifications)
- **View mode** uses `nodes`, `edges`, `positions` (skip parsing for speed)
